# 角色切换动效设计

## 目标

把桌面端五个角色的上下切换从大幅甩动改为轻柔接力。人物应保持舞台感：旧角色自然离场，新角色从相邻方向进入，右侧信息随后渐隐切换。移动端继续采用上下阅读布局。

## 范围

- 仅调整五个角色展示区的桌面端人物切换和右侧信息淡入节奏。
- 不改变角色顺序、文案、图片尺寸、页面底色、滚动吸附与旅行家交互。
- 不改变宽度小于或等于 1020px 时的角色排列方式。

## 桌面端结构

桌面端左侧固定舞台同时挂载五个角色形象，每个形象绝对定位在同一基准线上。当前角色由现有 `activeIndex` 控制，其他角色根据索引位于舞台上方或下方。

各身份触发区仍保留人物节点供移动端使用，但桌面端不再显示这些随页面直接滚动的人物，避免滚动位移与 CSS 过渡叠加。

右侧继续使用现有固定内容舞台和五个叠放面板，不改变内容组件。

## 动效参数

### 人物

- 当前人物：`translateY(0)`、`scale(1)`、完全不透明。
- 已离场人物：向上移动 `16svh`、缩放至 `0.985`、透明度归零。
- 待入场人物：从下方 `16svh`、缩放 `0.985`、透明度为零。
- 持续时间：`850ms`。
- 曲线：`cubic-bezier(0.22, 0.8, 0.25, 1)`，先完成主要位移，再柔和减速。
- 入场和离场同时发生，两个人物会在低透明度阶段短暂交叠，新人物逐步取得视觉中心。

### 右侧信息

- 离场面板在 `480ms` 内淡出。
- 入场面板延迟 `100ms` 后，在 `560ms` 内淡入。
- 信息面板不做大幅位移，仅允许最多 `8px` 的纵向漂移，以人物动效为视觉主角。

## 响应式与无障碍

- 宽度小于或等于 `1020px` 时沿用现有移动端结构，不增加自动人物动画。
- `prefers-reduced-motion: reduce` 下移除人物位移、缩放与过渡，只保留即时状态切换。
- 非当前人物使用 `aria-hidden`，人物图片保持装饰性空替代文本，身份名称由对应内容区提供。

## 状态与触发

继续使用现有 IntersectionObserver，根据五个全屏触发区中可见比例最大的项目更新 `activeIndex`。不增加滚动监听或逐帧计算，避免滚动性能下降。

## 验收标准

1. 桌面端每次切换的人物位移不超过 `16svh`，不再出现整个人物快速飞出画面的效果。
2. 五个角色使用完全一致的入场、离场曲线和基准位置。
3. 右侧信息在人物开始切换后轻微延迟淡入，没有闪白或内容叠加造成的可读性问题。
4. 每个桌面角色触发区保持一屏高度，旅行家页面不会再次被隐藏内容撑长。
5. 移动端人物、地球和照片轮播布局保持现状。
6. 开启减少动态效果时不执行位移或缩放动画。

## 验证

- 运行生产构建，确认组件和样式编译通过。
- 检查桌面断点下五个人物舞台状态类与右侧面板状态同步。
- 检查移动断点仍显示各触发区中的人物内容。
- 检查减少动态效果媒体查询覆盖新增动画。
